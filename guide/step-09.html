Step 9 of 10

Prove the governance guardrails

Policies are only useful if they bite. Check compliance, try to run a privileged pod from a public image and watch the cluster refuse it, try to create a resource outside Indonesia, and trace every change back to an identity.

15 minAzure portalGitHubGovernanceSecurity

What you will do#

  • Review the three policy assignments and their compliance.
  • Get a privileged pod with a public image denied at admission.
  • Get a resource outside Indonesia Central denied by Azure Resource Manager.
  • Trace deployments to the GitHub identity in the activity log.

Policy compliance#

  1. Open Policy, Compliance and set the scope to rg-contoso-health-aks.

  2. Three assignments: pod security baseline, allowed images, allowed locations. Open one to see compliant and non-compliant resources and the non-compliance message.

  3. New assignments need up to 30 minutes for the first evaluation; the Azure Policy add-on syncs its constraints into the cluster on a similar schedule.

A non-compliant pod is denied#

  1. Open the cluster, Kubernetes resources, Workloads, Create, Apply a YAML.

  2. Paste the manifest below and select Add.

  3. Gatekeeper, managed by the Azure Policy add-on, rejects the pod: the image is not from the approved registry and the container asks to be privileged.

  4. Alternative without the portal: Actions, Demo scenarios, policy-check runs a server-side dry run of the same manifest.

k8s/demo/policy-violation.yaml
# Governance demo: this pod breaks two Azure Policy guardrails on purpose.
#  1. The image does not come from the approved Azure Container Registry.
#  2. It asks for a privileged container.
# Apply it from the portal (AKS > Kubernetes resources > Workloads > Create > Apply a YAML)
# and Azure Policy (Gatekeeper) rejects it at admission time.
apiVersion: v1
kind: Pod
metadata:
  name: policy-test
  namespace: contoso-health
  labels: { app: policy-test }
spec:
  containers:
    - name: nginx
      image: docker.io/library/nginx:1.27
      securityContext:
        privileged: true

A resource outside Indonesia is denied#

  1. In rg-contoso-health-aks select Create and pick a simple resource such as a network security group.

  2. Set the region to East US and select Review + create.

  3. Validation fails with RequestDisallowedByPolicy and the message Contoso Health guardrail. Nothing is created.

Who changed what#

  1. Open the resource group, Activity log. Deployments and role assignments are attributed to id-github-contoso-health, the identity behind every pipeline run.

  2. Access control (IAM): the identity holds three roles at this scope only; you hold AKS RBAC Cluster Admin on the cluster.

  3. Tags: every resource carries the tags from Bicep, ready for Cost Management.

Check your work#

  • Policy compliance lists three assignments for the resource group.
  • Applying policy-violation.yaml fails with a Gatekeeper denial that names the Azure Policy constraint.
  • Creating a resource in East US fails validation with RequestDisallowedByPolicy.
  • The activity log attributes the deployments to the GitHub identity.

How it works#

Guardrails at three layers. Azure Resource Manager policies (allowed locations) stop non-compliant resources before they exist. Kubernetes policies (pod security baseline, allowed images) are translated by the Azure Policy add-on into Gatekeeper constraints and enforced at admission, for kubectl, the portal and pipelines alike. Inside the namespace, Pod Security Admission labels warn and audit against the restricted profile, and NetworkPolicies limit which pods can talk.

Scope is a choice. The assignments are at resource-group scope so the demo stays self-contained. In production you assign them at a management group so every subscription inherits them, and exempt with a reason rather than delete.

What these policies do not cover

The allowed-locations assignment governs rg-contoso-health-aks only, not the AKS-managed node resource group. The allowed-images policy checks the contoso-health namespace only. Neither replaces image signing or vulnerability scanning of the images themselves.
