Outcome

Infrastructure as code

Everything the demo needs is described in the repository, from the first resource group to the last NetworkPolicy. The platform changes only through pull requests, previewed with what-if and deployed by a workflow behind an approval. Nobody holds a secret.

IaC at every layer#

LayerToolPathRun byWhen
Bootstrap: resource group, deployment identity, federated credentials, role assignmentsBicep, subscription scopeinfra/bootstrapA subscription admin (Cloud Shell, or the Deploy to Azure button)Once, before anything else
Repository settings: environment and reviewer, variables, rulesetTerraform, integrations/github providergithub/A repository admin (Cloud Shell)Once, and when settings change
Platform: AKS, registry, monitoring, alert rules, policyBicep, resource-group scopeinfra/GitHub Actions with OIDC, after approvalEvery merged change under infra/
Workloads: Deployments, Services, HPA, PDB, NetworkPoliciesKubernetes manifests, Kustomizek8s/GitHub Actions with OIDC, after approvalEvery merged change under src/ or k8s/

Two tools, on purpose: Bicep is the native language for Azure resources, with what-if and day-zero support for new API versions. GitHub settings are not Azure resources, so the GitHub provider for Terraform manages them. scripts/bootstrap.sh chains the two: the Bicep outputs (client ID, tenant, subscription) become Terraform inputs.

Steps 2 to 4 of the guide show both paths: the portal and GitHub clicks, and the same result as code (example).

Parameters that are safe to commit live in main.bicepparam; identity values come from repository variables at run time:

infra/main.bicepparam
using './main.bicep'

// Values that are safe to commit. Identity values come from GitHub repository variables
// and are injected as environment variables by the workflow (never hard-coded here).
param workloadName = 'contoso-health'
param environmentName = 'demo'
param nodeVmSize = readEnvironmentVariable('AKS_NODE_VM_SIZE', 'Standard_D4ds_v5')
param nodeMinCount = 2
param nodeMaxCount = 4
param aksTier = 'Free'
param policyEffect = 'Deny'
param appNamespace = 'contoso-health'
param deploymentPrincipalId = readEnvironmentVariable('AZURE_PRINCIPAL_ID', '')
param adminPrincipalId = readEnvironmentVariable('ADMIN_PRINCIPAL_ID', '')
param alertEmail = readEnvironmentVariable('ALERT_EMAIL', '')

How a change flows#

  1. Edit a file under infra/ on a branch and open a pull request.
  2. The What-if job signs in with the pull-request credential and comments the planned changes (Create, Modify, Delete, NoChange) on the pull request.
  3. Reviewers read the diff and the what-if together. Required checks validate the Bicep (bicep build and lint).
  4. Merging to main starts the deploy job, which waits at the production environment for approval.
  5. Azure Resource Manager applies the template incrementally and the App workflow re-deploys the workloads.

Where to see it#

  • GitHub: the pull request what-if comment, the workflow run summary with outputs, the production environment deployment history.
  • Azure portal: the resource group, Settings, Deployments: every run as infra-<run number> with its inputs, outputs and template.
