Outcome

Governance

Governance here is a set of controls that each say no to something specific, configured as code or as repository settings, and visible to anyone who looks.

Controls by layer#

Policy as code#

infra/modules/policy.bicep (excerpt)
resource allowedImages 'Microsoft.Authorization/policyAssignments@2024-04-01' = {
  name: 'aks-allowed-images'
  properties: {
    displayName: 'Contoso Health: only images from the approved container registry'
    description: 'Containers in the application namespace may only run images from the Contoso Health Azure Container Registry.'
    policyDefinitionId: builtIn.allowedImages
    enforcementMode: 'Default'
    parameters: {
      effect: {
        value: effect
      }
      namespaces: {
        value: [
          appNamespace
        ]
      }
      allowedContainerImagesRegex: {
        value: '^${replace(acrLoginServer, '.', '\\.')}/.+$'
      }
    }
    // No nonComplianceMessages: not supported for 'Microsoft.Kubernetes.Data' mode definitions.
  }
}

Network policy#

k8s/base/network-policies.yaml (excerpt)
# Back-end APIs accept traffic only from the portal and from the metrics agent in kube-system.
apiVersion: networking.k8s.io/v1
kind: NetworkPolicy
metadata:
  name: allow-api-from-portal-and-monitoring
spec:
  podSelector:
    matchExpressions:
      - { key: app, operator: In, values: [membership-api, bed-api] }
  policyTypes: [Ingress]
  ingress:
    - from:
        - podSelector:
            matchLabels: { app: portal }
        - namespaceSelector:
            matchLabels: { kubernetes.io/metadata.name: kube-system }
      ports:
        - { port: 8080, protocol: TCP }
