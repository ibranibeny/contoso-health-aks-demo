Workflows and identity

Seven workflows. Four sign in to Azure, and each job's OIDC subject decides which federated credential it can use. Every workflow can be started from the Actions tab; the ones marked API also accept a repository_dispatch event, which is how this demo was run end to end.

Running the demo by API#

Everything the guide does in the UI can be driven by API calls with a token that has admin rights on the repository. Approvals still go through the production environment.

GitHub CLI
# Start the infrastructure deployment
gh api repos/OWNER/REPO/dispatches -f event_type=deploy-infra
# Run a demo scenario
gh api repos/OWNER/REPO/dispatches -f event_type=demo -F client_payload[scenario]=policy-check
# Approve a waiting deployment (run ID from the Actions tab)
gh api repos/OWNER/REPO/actions/runs/RUN_ID/pending_deployments \
  -F environment_ids[]=ENV_ID -f state=approved -f comment="Reviewed"

Pinned actions#
